# Arrow Puzzle: rules for Claude Code

Unity 6 mobile game (portrait, Android). Whole UI is built **in code**; never edit scenes, prefabs or the Inspector.

- Follow `UI_SPEC.md` exactly (colors, sizes, spacing, texts). It is the approved design.
- Work on **one screen at a time**, only the screen named in the prompt. Do not touch other screens or the game logic unless the prompt says so.
- One screen = one file in `Assets/ArrowPuzzle/Scripts/`: `ScreenXxx.cs`, or `PopupXxx.cs` (override `IsPopup => true`), deriving from `AppScreen`. GameApp finds it automatically; do not register it anywhere.
- Build UI only with `Ui`, `Theme`, `Icons` and `ArrowGraphic`. Sizes are design px (`Ui.PlaceD`, `Theme.D`, the `...D` parameters). Never hard-code canvas units or colors; use `Theme` fields.
- Fonts only through the `Weight` enum (Fredoka files are in `Resources/Fonts`).
- Navigate by name (`GameApp.I.Show("ScreenHome")`, `Open("PopupPause")`) so screens can be built in any order. A missing screen only logs a warning.
- Do not change `Theme`, `Ui`, `Icons`, `GameApp`, `AppScreen` unless a screen truly needs something missing; then make additive changes only and say so.
- You cannot run Unity: re-read your code for compile errors (missing usings, wrong names) before finishing.
- Finish with a short report: file(s) created, what the screen does, anything that differs from the spec.

## Level path
- One path of 150 levels (`LevelPath.Count`); the player does not pick a mode. Global level g cycles the three types `enum GameMode { Classic, Shapes, Mosaic }` (50 each, `ModeInfo.LevelsPerMode`): `LevelPath.TypeOf(g)`, `TypeLevelOf(g)`, `Global(type, typeLevel)`, `TypeName(g)`, `Difficulty(g)`. `GameApp.I.CurrentLevel` is the global level; `CurrentMode` is its type, set by the game screen.
- Display data per type: `ModeInfo.Get(mode)` -> `Name`, `Tagline`, `Color`, `Edge`, `Tint`.
- Level data: always `Levels.For(type, typeLevel)`. Classic = `LevelGen.Generate`; Shapes / Mosaic come from `Resources/Levels/shapes.txt` / `mosaic.txt` via `ShapeLevels` (have `LevelData.mask[x, y]`, y up, and `shape`). An editor self check logs "ShapeLevels: 100 levels OK" on play; "ArrowPuzzle/Check level path" checks all 150.
- Progress: `Save.UnlockedGlobal` (key "unlockedGlobal"), `Save.IsUnlocked(g)`, `Save.IsCompleted(g)`, `Save.LevelWon(g)`, `Save.CompletedLevels()`, `Save.TotalStars()`. Stars and best times stay per type: `Save.Stars(type, typeLevel)` / `SetStars(type, typeLevel, s)` (Classic keeps the old keys). `Save.UnlockAllLevels` is a dev switch: keep it false for release.

## Ads
- Only `Ads.cs` talks to the Google Mobile Ads SDK (v11.6.0). `Ads.TestMode = true` uses Google's test units; set it false for release. Every ad unit ID lives in `AdIds` (Ads.cs): a test const and a real const per ad (`AppOpen`, `Banner`, `Interstitial`, `Rewarded`, `NativeWin`, `NativeLose`). An empty real ID = that ad is off.
- The IDs come only from those in-code constants (no runtime override, no Remote Config): paste the real AdMob IDs into `AdIds` before release.
- Banner: one anchored adaptive `BannerView` at the bottom, `Ads.Banner(bool, screen)` per screen (a show wins over a hide in the same frame). `Ads.BannerHeightDesign` / `BannerHeightChanged` move the game screen's buttons. PopupWin / PopupLose hide it in OnShow and give it back in OnHide via `ScreenGame.RestoreBanner` (every route). A height change while hidden is applied on restore.
- Interstitial: on PopupWin Next / Home (not after the very first level completed). Rewarded: PopupLose "Watch ad · +1 life".
- Result screens: PopupWin (Level complete) and PopupLose (Out of lives) are still popups (`IsPopup`), but full screen: a cream `Theme.Bg` image over the whole screen (blocks taps to the game), content in a `Safe` rect (`Ui.FitSafeArea`, re-fitted in OnShow). All positions are fixed, in design px from the safe-area top (no layout groups), so nothing moves when "Video not ready" shows. Text gaps are measured on Fredoka's ink: a centred `Text` of size s inks from about y - 0.333 s to y + 0.391 s.
- Native (`NativeOverlayAd`, medium or small template, white / ink / teal CTA): `NativeKind { Win, Lose }`, one loaded ad per kind (the template is picked when it is rendered, so the same ad can be medium or small). `Ads.PreloadNative(kind)` at every level start (ScreenGame.StartLevel); retries after 30 s, then 60 s. `Ads.PlanNative(rowBottom, who)` takes free space = bottom of the button row + 12 dp to the safe-area bottom. Medium first, always: medium if free >= 350 + 14 + 8 (8 dp bottom margin above the gesture bar); else squeezed medium down to `Ads.NativeMediumMinDp` (350: the template keeps its exact 350dp inside a shorter view, so 300 / 280 / 260 all clip the CTA, which means no squeeze today); Small only as the last resort, logged as a warning. Template heights: `Ads.NativeMediumDp` = 350 (the plugin's gnt_medium_template_view.xml fixes its root at 350dp, at every width; less cuts off the CTA) and `NativeSmallDp` = 100 (the small layout fills what it gets). Ad rect: 328 design px wide (frame 342 minus 2 x 7), design -> px -> dp, centred, top = frame top + 7. Plugin quirk (11.6 Android): a custom AdSize goes straight into the view's LayoutParams as PIXELS while x / y are dp, so `Render` passes the AdSize as dp x density. A few frames after rendering, `CheckLayout` logs the laid-out size; a medium that came out taller than planned is re-rendered small (`Ads.ShownNativeSize`, the frame follows). `Ads.ShowNative(kind, plan, size)` / `HideNative()` (hide = destroy, then preload the next). Android only: Editor / other platforms, `InitFailed` or an empty ID = off, no-op with a log.
- Result screen button rows (frees the space for a medium ad): Level complete = round white Home (60, 3 px #D9D1C1 edge) + 12 + NEXT LEVEL (270x60), both at y 366; Out of lives = Watch ad (342x72) row, then Restart level (274x56, white) + 12 + round Home (56). Both rows end at 431 design px from the safe-area top (normal). Compact layout (t = 1): ribbon 52, stars 64 / 48, other gaps about 80 %, rows end at 392 (Win) / 390 (Lose). Text and button sizes never change; label -> digits (37) and digits -> badge (55) stay fixed so those ink gaps stay >= 12 px.
- dp / px: one display source for the banner and native ads (`Ads.ReadDisplay`): Android `DisplayMetrics.density` and `widthPixels` (Screen.dpi / Screen.width in the Editor). Unity px are scaled by widthPixels / Screen.width in case Unity renders at a lower resolution.
- `NativeAdSlot` (NativeAdSlot.cs) is the screen side: `Create(body, kind, who)` in Build, `Plan(t => rowBottomAt(t))` in OnShow (tries the normal layout, then compact steps 1..4 down to 80 % spacing, re-planning each time, until medium fits; returns t and the screen calls its `ApplyLayout(t)`) (sizes the permanent white frame: radius 22, 3 px #D9D1C1 edge, 7 px padding, 342 wide; hidden when None, off or the last load failed), `Begin()` once the content has settled (once per show), `End()` on every exit (OnHide; PopupWin also on its Next / Home / Back tap). While the ad loads, a medium or small skeleton shimmers in the frame's inner rectangle. The ad replaces it there; on failure or after 8 s the shimmer fades out (0.15 s) and the frame stays.

## Startup, consent and Firebase
- Launch order (`AppStartup`, from `GameApp.Awake`, never blocks the splash): UMP consent (`ConsentService`: Google's form only where required; 8 s update / 60 s form timeouts) -> `Ads.ReleaseInit()` the moment UMP allows ad requests (a previous session's consent counts at once). `FirebaseBoot.Init` starts in parallel with consent and never delays ads. `Ads.HoldInit()` defers `Ads.Init` and queues loads until then. Ads start only if `ConsentService.CanRequestAds`. A late consent answer still applies. The splash waits up to 4 s (`ScreenSplash.AdWait`) for the launch app open ad, then goes Home.
- Ad unit IDs: `enum AdSlot` (8) in Ads.cs, `AdIds.Get(slot)`. Banner unit per screen: Home / Settings = `BannerHome`, the game and its popups = `BannerGame` (a unit change recreates the banner view). App open: splash = `AppOpenFirst`, later = `AppOpenResume`.
- Firebase (Analytics and Crashlytics only; no Remote Config SDK) only in three files: `FirebaseBoot` (CheckAndFixDependencies, `Ready` / `OnReady`), `AnalyticsService` (events queued until ready, max 50; consent mode from UMP / TCF), `CrashReporter` (Log, SetKey, Breadcrumb on every screen / popup change in GameApp; `TestCrash` only in Editor / development builds). Every Firebase call is wrapped in try/catch.
- Editor: "ArrowPuzzle/Check Firebase setup" (google-services.json, package name, Analytics and Crashlytics assemblies).
- Consent defaults: `Assets/Plugins/Android/ArrowPuzzleConsent.androidlib` (a merged library manifest, not a custom main manifest) starts Analytics with collection off and all four `google_analytics_default_allow_*` signals denied. `AnalyticsService` turns collection on only when the UMP / TCF result grants analytics storage (also when GDPR does not apply). No TCF data yet = granted only if UMP's ConsentStatus is NotRequired. Crashlytics stays on (not a consent purpose).
- Settings MORE rows: Share this game, Rate us, Music credits (when credits exist), Privacy options. There is no in-app privacy policy link (removed on purpose; `AppLinks` keeps only Share and Rate).
- Settings "Privacy options" (last row of MORE) shows only when `ConsentService.PrivacyOptionsRequired`; it opens UMP's privacy options form, then `ConsentService.Changed` re-applies Analytics consent and starts ads if they now may run.
- UMP debug: `ConsentService.DebugForceEea` + `DebugTestDeviceHashedId` (compiled only in the Editor / development builds).
